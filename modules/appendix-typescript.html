一、第一件事：类型标注是注释

ts
// packages/coding-agent/src/core/tools/render-utils.ts:80-83export type ToolRenderResultLike<TDetails> = {	content: (TextContent | ImageContent)[];	details: TDetails;};

TDetails 是待填的参数，content 后面的 (TextContent | ImageContent)[] 是「数组，元素是这两种之一」。这些冒号后面的东西运行时全部消失， 编译产物里只剩 {}。读的时候可以当注释看。

Python 侧：

python
# 近似写法：类型标注在运行时同样不强制@dataclassclass ToolRenderResultLike(Generic[TDetails]):    content: list[TextContent | ImageContent]    details: TDetails

一句总纲：看类型标注是为了知道「这里装的是什么」，不是为了看它怎么实现。

二、八种只有读源码才会遇到的写法

2.1 联合类型 A | B：一个变量几种形状

ts
// packages/ai/src/types.ts:489export type StopReason =	| "pending" | "stop" | "length" | "toolUse"	| "error" | "aborted" | "deferred";

七个字符串之一。七值归属表在 M03 §6.1；三个"还在产出、已经没人读"的取值在 M03 §6.7。

Python 是 Literal：

python

2.2 判别联合 + never：漏一种就编译不过

AgentMessage 是八种消息的联合，它们的 role 字段各不相同——这个字段 叫判别键。有了它，switch (m.role) 的每个 case 里，m 会被自动 收窄成对应的那一种：

ts
// packages/coding-agent/src/core/messages.ts:148-196（节选）switch (m.role) {	case "bashExecution":		if (m.excludeFromContext) return undefined;		return { role: "user", content: [], timestamp: m.timestamp };	case "compactionSummary":		return { role: "user", content: [], timestamp: m.timestamp };	// …另外几种自定义消息同理	default:		// biome-ignore lint/correctness/noSwitchDeclarations: fine		const _exhaustiveCheck: never = m;		return undefined;}

最后那行是全书最重要的三行类型代码之一。原理：八种都写过 case 之后， m 被收窄成 never（不可能是任何东西），赋值才通过。漏掉一种， m 就不是 never，这行直接编译报错——「加了消息类型忘了改转换器」 从此是编译期错误，不是线上静默丢消息。

M06 §3.3 完整讲过这段（m06:325-338）。

Python 没有等价物。match 语句可以穷尽，但漏了分支只在运行时炸。

2.3 泛型 <T>：待填的类型参数

ts
// packages/ai/src/models.ts:275getModelsOfType<TType extends ModelType>(	type: TType,	provider?: string,): readonly ModelTypeMap[TType][];

读法：<TType extends ModelType> 是「调用时再定的类型，但必须是 ModelType 之一」；返回值的 ModelTypeMap[TType] 是按 TType 查表拿到的 具体类型。传 "chat" 拿到聊模型列表，传 "image" 拿到图像模型列表—— 同一个函数，返回类型跟着参数走。

Python 用 TypeVar：

python
TType = TypeVar("TType", bound=ModelType)async def get_models_of_type(    t: TType, provider: str | None = None,) -> list[ModelTypeMap[TType]]: ...

实际差别：Python 的类型参数运行时还在（可反射），TS 的编译后消失。

2.4 类型谓词 is：收窄的开关

ts
// packages/ai/src/models.ts:1232export function hasApi<TApi extends Api>(	model: AnyModel,	api: TApi,): model is Model<TApi> {

返回类型写 model is Model<TApi> 而不是 boolean。这意味着只要 if (hasApi(m, "anthropic-messages")) 成立，m 在分支里就变成 Model<"anthropic-messages">，可以访问该 API 的专属字段。

它为什么必需，源码自己在 models.ts:270 写了：动态模型列表的类型是宽的 Model<Api>，要用 hasApi() 收窄。Python 侧是 TypeGuard，用法几乎一样。

同一个写法在 M15 又出现一次，而且用得更高：Validator.check 的类型是 (value: unknown) => value is T（schema/src/validator.ts:202）——编译出来 的闭包兼任类型谓词，if (v.check(x)) 之后 x 直接就是 T。这就是 M15 §2 那句"编译产物与类型谓词合并成一件事"。

2.5 条件类型：类型层面的 if

ts
// packages/ai/src/types.ts:640-646（节选）export type ToolResultMessage<TDetails = JsonValue> =	IsJsonCompatible<TDetails> extends true		? {				role: "toolResult";				toolCallId: string;				toolName: string;				content: (TextContent | ImageContent)[];				details?: JsonRepresentation<TDetails>;				// …			}		: never;

X extends true ? A : never 就是「不合规就变成 never」。配套的工具类型 在同文件 :494-537：

  • IsJsonCompatible<T>：递归判断能不能安全落盘（函数、undefined、 Symbol 都判假）
  • InvalidJsonKeys<T>：反向找出哪个键不合法，报错能指到字段
  • JsonRepresentation<T>：把内存类型映射成「落盘后的形态」

为什么值得：details 的唯一归宿是 jsonl 文件（M10）。塞 Date 进去落盘 变字符串，塞 Map 进去变 {}——错误在落盘那一刻才暴露。M06 §3.5 （m06:367-390）是这个设计的完整动机。

Python 只有 TypeVar + 重载能近似，没有真正的条件类型。

条件类型里还能就地声明一个类型变量，用 infer：

ts
// packages/chord/src/contract.ts:417-424（节选）export type ImplementationOf<C, P = unknown> =	C extends RemoteContract<infer D> ? ... : never;

读作"如果 C 长得像 RemoteContract<D>，就把那个 D 记下来"。 as 是断言（不检查、我说了算），infer 是反推（检查，并从里面取出一个 类型变量）——两者长得很像，方向正好相反。正文里 M12 §3.4 用它把 contract 的类型参数掏出来。

2.6 satisfies：检查，但别改我的类型

ts
// packages/coding-agent/src/core/keybindings.ts:171} as const satisfies KeybindingDefinitions;

as const 把对象冻成字面量类型（键名保留、值不可变），satisfies 再拿它 去比对 KeybindingDefinitions 的形状。叠加效果：既被校验，又保留字面量 的精确类型——这正是写配置表最想要的。

对比标注写法 : KeybindingDefinitions：校验过了，但类型被放宽，字面量 信息丢了。

satisfies 在正文出现六次。例如 agent-loop.ts:620 } satisfies FinalizedToolCallOutcome;——返回值不写标注而用 satisfies， 就是为了让调用方拿到精确的联合成员。

2.7 as const：把字面量冻成常量

ts
// packages/coding-agent/src/core/tools/bash.ts:47} as const;

工具定义里到处是这个。bash.ts:44-47 给的是工具的提示词贡献：

ts
// packages/coding-agent/src/core/tools/bash.ts:44-47export const bashToolSystemPromptContribution = {	snippet: "Execute bash commands (ls, grep, find, etc.)",	guidelines: ["You can inspect PI_* environment variables …"],} as const;

三、进阶十种：源码里就那么写

下面十种在 1,004 个源文件（不含测试与脚本）里合计出现 2,001 次， 正文却大多只说了一句「这里用了 X」。它们的难点不是认出符号，而是知道 去掉它会坏在哪。

3.1 #x：真私有，类外拿不到（1,043 处）

ts
// packages/durable/src/session/session.ts:262-277（节选）#current: Job | undefined;#fence: Promise<void> = Promise.resolve();#outstanding = 0;readonly #ownOutcomes = new Set<number>();#failure: { readonly error: unknown } | undefined;readonly #failed = Promise.withResolvers<never>();

private 只是编译期约定：产物里还是普通属性，(x as any).foo 摸得到， Object.keys 也看得见。#x 是语言级私有：类外访问直接是语法错误，子类 也拿不到。

上面这段是教科书级用法——#fence（等所有 job 落地的闸门）、#outstanding （未交付计数）、#failed（失败信号）全是内部状态机，一个都不该出现在公开 形状里。

readonly #x 是两者叠加：外部可读、不可写，写只发生在字段初始化与构造器。 注意它锁的是引用，#ownOutcomes 那个 Set 照样能往里加。

Python：_x 是约定，__x 只是改名（_Class__x 仍可访问）。没有真私有。

3.2 get / set：调用时不带括号（347 处）

ts
// packages/coding-agent/src/core/agent-session.ts:1461-1478（节选）get state(): AgentState {	return this.agent.state;}get cacheWarmingStatus(): CacheWarmingStatus | undefined {	return this._cacheWarmer?.status;}get model(): Model<any> | undefined {	return this.agent.state.model;}

调用处写 session.state，不写 session.state()。读代码时看到没有括号的 属性访问，先怀疑它是 getter。

三个 getter 都在转发，不是复制：state 每次现取底下的 agent 状态， cacheWarmingStatus 现算，底层一改立刻可见。这是刻意的——session 是可重放 的投影层，缓存一份状态，迟早和真相不一致。

判据：getter 内部只要有 if、?. 或函数调用，它就是「惰性计算 + 只读视图」， 不是字段。源码里 347 处 getter 大半是这个用途。

Python：@property，一模一样。

3.3 async * / yield：手写异步迭代器（160 处）

ts
// packages/ai/src/utils/event-stream.ts:72-84（长行按版面折过）async *[Symbol.asyncIterator](): AsyncIterator<T> {	while (true) {		if (this.queue.length > 0) {			yield this.queue.dequeue()!;		} else if (this.done) {			return;		} else {			const result = await new Promise<IteratorResult<T>>(				(resolve) => this.waiting.enqueue(resolve),			);			if (result.done) return;			yield result.value;		}	}}

yield x 不是「返回」，是把 x 交给调用方然后停在这一行，下次 .next() 从下一行继续。所以 while (true) 里没有 break，靠 return 结束。

这段挂在 [Symbol.asyncIterator] 上，意思是「这个对象可以被 for await 吃」。 M04 里那句 for await (const event of stream) 走的就是这十几行：队列有货就 yield，已结束就 return，都没有就挂起，把 resolve 塞进 waiting 队列 ——另一头是 push()（:52-57），谁先来谁唤醒谁。

Python：async def + yield 几乎同构，return 对应 StopAsyncIteration。 差别只在 Python 会把它写成独立函数，TS 这里直接写在类上。

3.4 as unknown as：跨家族断言（138 处）

ts
// packages/durable/src/codemode/codemode.ts:431start: copyJson(run.start as unknown as JsonValue) as unknown as Start,

单次 as 只能在同一家族里换说法：子类型转父类型、联合转成员。Start 和 JsonValue 互不包含，直接转会以「两个类型没有充分重叠」被拒。走 unknown 中转，等于明说「这两者没关系，我知道自己在干什么」。

这里不是骗编译器：copyJson() 真的做了一次 JSON 深拷贝（下一行 :432 的 journal 同理），断言断的是「往返一次之后，形状还是原来那个」。这类位置 值得信任。

判据：看到 as unknown as 先问中间是不是过了序列化、反射或代理。是，就是 合法逃生舱；不是，多半是懒得写类型，值得怀疑。

Python：cast(Any, x) 再 cast(Start, x)，或者干脆 json.loads(json.dumps(x))。

3.5 override：覆写要写出来（108 处）

ts
// packages/tui/src/tui-alt-screen.ts:335-347（节选）override render(width: number): string[] {	return this.layoutRoot?.render(width) ?? super.render(width);}protected override getMountedRoots(): readonly Component[] {	return this.layoutRoot ? [this.layoutRoot] : this.children;}

它不改变运行时行为，只加一条编译期检查：父类必须真有同名成员。开了 noImplicitOverride 之后，漏写 override 也报错。

读法：看到 override 就知道「这一层改写了父类行为」，往上翻一层看原版。 super.render(width) 配合 ??，是「没有自定义布局就交回父类」。

Python：没有对应关键字。覆写是隐式的，父类改了名，子类会静默变成新方法 ——这正是 TS 加这个关键字的理由。

3.6 Promise.withResolvers：把开关留在自己手里（41 处）

ts
// packages/durable/src/session/session.ts:276-281readonly #failed = Promise.withResolvers<never>();readonly #closed = Promise.withResolvers<SessionEnd>();get closed(): Promise<SessionEnd> {	return this.#closed.promise;}

老写法要先声明一个 let resolve!，再 new Promise((r) => (resolve = r))， 还得跟「构造器里回调一定执行过」的类型问题较劲。withResolvers() 一次给出 { promise, resolve, reject }：promise 挂字段上给外面 await，resolve 藏在私有方法里，只有类自己能让它落地。

两个细节值得记：<never> 表示这个 promise 只会 reject（resolve 的 参数类型是 never，正常调用写不出来）；get closed() 每次返回同一个 promise，不是新建一个。

Python：asyncio.Future()，set_result / set_exception 一一对应。

3.7 <const T>：让字面量别被放宽（39 处）

ts
// packages/schema/src/builders.ts:85-109（节选）export function lit<const V extends string | number | boolean | null>(	value: V,	options: Annotations<V> = {},): Schema<V> {	return { const: value, ...options };}export function union<const S extends readonly Schema[]>(	schemas: S,	options: Annotations<Static<S[number]>> = {},): Schema<Static<S[number]>> {	return { anyOf: schemas, ...options };}

没有 const 时，数组实参会被推成 Schema[]、string[] 这种宽类型， S[number] 也就退化成 Schema、string 了：校验还在，类型提示全丢。 加了 const，实参保留成 readonly […]，S[number] 才能精确到具体成员。 oneOf(["text", "image"])（:93）就是同一个道理：不加 const 拿到的是 Schema<string>，加了才是 Schema<"text" | "image">。

把它当成「函数参数版的 as const」最好记：调用处不用再写 as const， 由签名负责把字面量钉住。这是 TS 5.0 的语法，本书对应版本里已经用得很顺 （contract.ts:72、declare.ts:71-76 也是）。

为什么非它不可：M15 讲「编译产物与类型同源」，靠的就是 Static<S> 能 一路推到字面量。放宽成 string，那套推断就断了。

Python：Literal["text"] 天生精确，没有「放宽」这回事。

3.8 函数重载：一个名字，几份目录（33 处）

ts
// packages/chord/src/next/contracts/schema.ts:79-80（签名）export function num(	options: Bounds & { readonly default: number },): NumberSchema & Defaulted<number>;export function num(options?: Bounds): NumberSchema;

同一个 num 写了三遍：前两段没有函数体，是给调用者看的目录；第三段 （:81）才有 { ... }，是唯一实现，参数类型是 Bounds & { readonly default?: number }，必须同时接住上两种调用。

为什么不用条件类型写返回值：num({ default: 3 }) 要返回 NumberSchema & Defaulted<number>（能直接取值），num() 只要 NumberSchema。 两行签名比一个三层条件类型好读得多。

读法：看到同名函数连着出现、前面的都以 ; 结尾，就是重载。正文里的 streamSimple / complete 也是这个写法（M04 §三）。

Python：@overload 堆 stub + 一个实现，思路完全一样。

3.9 映射类型 + 索引访问：在类型层面遍历键（82 处）

ts
// packages/chord/src/contract.ts:79-81type StringKeys<I> = {	[K in keyof I]-?: I[K] extends string ? K : never;}[keyof I] & string;export type PlacementFor<I> = HostNamed | HostFamily<StringKeys<I>>;

一行四件事：[K in keyof I] 遍历所有键、-? 去掉可选、 I[K] extends string ? K : never 把「值不是 string」的键变成 never、 最后的 [keyof I] 把这张表按所有键索引，取出值的联合。never 会从 联合里自动消失，剩下的就是「必填且为 string 的键名」。& string 再把 数字键筛掉。

读法：先看结尾有没有 [keyof X]。有，整个映射类型就是在「筛键」； 没有，结果是一张同形状的新表。这里拿它约束 hostFamily 只能用「输入里 必填的字符串字段」当宿主名，运行时那段 :84-89 正好对应。

另一种用法在 packages/chord/src/cell.ts:308： { [K in keyof S]: S[K] extends Readable<infer T> ? T : never }， 把「一组 Readable」变成「一组值」，infer 就是 §2.5 那个。

Python：没有。这类「类型层遍历」只能手写每个类。

3.10 unique symbol：给 number 贴标签（10 处）

ts
// packages/durable/src/types.ts:18-26（节选）declare const idBrand: unique symbol;export type Id<Kind extends string, Type = unknown> = number & {	readonly [idBrand]: { readonly kind: Kind; readonly type: Type };};

unique symbol 是类型层面的常量：declare const 保证它运行时不存在、 不占一个字节，但类型系统里独一无二。于是 number & { [idBrand]: ... } 在结构上仍是 number（能算、能比较、能落盘），却和裸 number 不兼容： 把 EntryId 传给要 ConversationId 的地方，直接报错。

这叫品牌类型（branded type）。TS 没有 nominal 关键字，这是标准做法。

进入这个类型的方式只有断言一次：types.ts:40 那句 ROOT_CONVERSATION_ID = 1 as ConversationId。全库只在那一处允许， 之后所有 id 都带着标签流转（M11 的会话树全靠这个）。

Python：NewType("EntryId", int)，运行时不检查，思路一致。

五、Node 运行时：四个绕不开的内建对象

源码里出现频率最高、Python 里又没有直接对应物的四个：

Buffer——字节数组。M13 的 stdio 传输整节都在用它拼字节 （stdio.ts:181-207）。Python 里是 bytes + bytearray。

child_process——起子进程。MCP 的 stdio 传输本质是 spawn 一个服务器 进程再读它的 stdout（stdio.ts:449 的 killProcessTree）。Python 里是 subprocess。

AbortSignal——取消令牌。长任务都带一个 signal 参数，用户按 Esc 就 abort()。Python 里是 asyncio.Task.cancel()。

queueMicrotask——把一个函数排到当前同步代码之后、下一次 IO 之前。 scheduler.ts:1871 用它做「合并多次唤醒」：

ts
// packages/durable/src/harness/scheduler.ts:1868-1874（节选）if (this.#draining || !this.#enabled || !this.#closing) return;this.#draining = true;queueMicrotask(() => void this.#drain());

M11 §五讲了这个循环的全部意义：没有 while，靠「再排一次」驱动。 Python 里最接近 asyncio.call_soon。

六、Python 程序员的三个真陷阱

一，[] 和 {} 是 truthy。 Python 里空列表是假值，JS 里是真值。 所以源码判断空数组一律 .length === 0，不会写 if (!arr)。

二，== 会隐式转换，=== 不会。 源码里清一色 ===（biome 有规则拦着）。 "8" == 8 在 Python 里是 False，在 JS 里是 true。

三，.map() 返回新数组，.forEach() 返回 undefined。 Python 的 列表推导返回列表，生成器函数返回迭代器——JS 没有同款惰性版。
