附录 B —— 读源码用的 TypeScript 速查

1,600 字 · 含 80 行代码 · 约 12 分钟

这本书的代码块全部来自 v1.4.0 源码，不是伪代码。所以读之前，你得能 看懂两种东西：TypeScript 的类型写法，和Node 运行时的几个内建对象。

不用会写。会认就行。

这一页只列正文里真正出现过、且 Python 里没有对应物的写法。每条三行： 写法长什么样 / 书里哪儿用过（可点坐标）/ Python 里怎么对应。

领域术语不在这里——差分、两阶段提交、幂等这些是业务概念， 各自在正文首次出现时给了定义，查它们请回对应章节。

一、第一件事：类型标注是注释

ts
// packages/coding-agent/src/core/tools/render-utils.ts:80-83export type ToolRenderResultLike<TDetails> = {	content: (TextContent | ImageContent)[];	details: TDetails;};

TDetails 是待填的参数，content 后面的 (TextContent | ImageContent)[] 是「数组，元素是这两种之一」。这些冒号后面的东西运行时全部消失， 编译产物里只剩 {}。读的时候可以当注释看。

Python 侧：

python
# 近似写法：类型标注在运行时同样不强制@dataclassclass ToolRenderResultLike(Generic[TDetails]):    content: list[TextContent | ImageContent]    details: TDetails

一句总纲：看类型标注是为了知道「这里装的是什么」，不是为了看它怎么实现。

二、八种只有读源码才会遇到的写法

2.1 联合类型 A | B：一个变量几种形状

ts
// packages/ai/src/types.ts:489export type StopReason =	| "pending" | "stop" | "length" | "toolUse"	| "error" | "aborted" | "deferred";

七个字符串之一。M03 §六整节都在讲这七个值分别什么时候出现。

Python 是 Literal：

python
StopReason = Literal[    "pending", "stop", "length", "toolUse",    "error", "aborted", "deferred",]

2.2 判别联合 + never：漏一种就编译不过

AgentMessage 是八种消息的联合，它们的 role 字段各不相同——这个字段 叫判别键。有了它，switch (m.role) 的每个 case 里，m 会被自动 收窄成对应的那一种：

ts
// packages/coding-agent/src/core/messages.ts:148-196（节选）switch (m.role) {	case "bashExecution":		if (m.excludeFromContext) return undefined;		return { role: "user", content: [], timestamp: m.timestamp };	case "compactionSummary":		return { role: "user", content: [], timestamp: m.timestamp };	// …另外几种自定义消息同理	default:		// biome-ignore lint/correctness/noSwitchDeclarations: fine		const _exhaustiveCheck: never = m;		return undefined;}

最后那行是全书最重要的三行类型代码之一。原理：八种都写过 case 之后， m 的类型被收窄成 never（不可能是任何东西），赋值才通过。漏掉一种， m 就不是 never，这行直接编译报错——它把「加了消息类型忘了改转换器」 变成了编译期错误，而不是线上的静默丢消息。

M06 §3.3 完整讲过这段（m06:325-338）。

Python 没有等价物。match 语句可以穷尽，但漏了分支只在运行时炸。

2.3 泛型 <T>：待填的类型参数

ts
// packages/ai/src/models.ts:275getModelsOfType<TType extends ModelType>(	type: TType,	provider?: string,): readonly ModelTypeMap[TType][];

读法：<TType extends ModelType> 是「调用时再定的类型，但必须是 ModelType 之一」；返回值的 ModelTypeMap[TType] 是按 TType 查表拿到的 具体类型。传 "chat" 拿到聊模型列表，传 "image" 拿到图像模型列表—— 同一个函数，返回类型跟着参数走。

Python 用 TypeVar：

python
TType = TypeVar("TType", bound=ModelType)async def get_models_of_type(    t: TType, provider: str | None = None,) -> list[ModelTypeMap[TType]]: ...

实际差别：Python 的类型参数运行时还在（可反射），TS 的编译后消失。

2.4 类型谓词 is：收窄的开关

ts
// packages/ai/src/models.ts:1232export function hasApi<TApi extends Api>(	model: AnyModel,	api: TApi,): model is Model<TApi> {

返回类型写 model is Model<TApi> 而不是 boolean。这意味着只要 if (hasApi(m, "anthropic-messages")) 成立，m 在分支里就变成 Model<"anthropic-messages">，可以访问该 API 的专属字段。

它为什么必需，源码自己在 models.ts:270 写了：动态模型列表的类型是宽的 Model<Api>，要用 hasApi() 收窄。Python 侧是 TypeGuard，用法几乎一样。

同一个写法在 M15 又出现一次，而且用得更高：Validator.check 的类型是 (value: unknown) => value is T（schema/src/validator.ts:202）——schema 编译出来的那个闭包，本身兼任类型谓词，所以 if (v.check(x)) 之后 x 直接 就是 T。这也是 M15 §2 那句"编译产物与类型谓词合并成一件事"的全部意思。

2.5 条件类型：类型层面的 if

ts
// packages/ai/src/types.ts:640-646（节选）export type ToolResultMessage<TDetails = JsonValue> =	IsJsonCompatible<TDetails> extends true		? {				role: "toolResult";				toolCallId: string;				toolName: string;				content: (TextContent | ImageContent)[];				details?: JsonRepresentation<TDetails>;				// …			}		: never;

X extends true ? A : never 就是「不合规就变成 never」。配套的工具类型 在同文件 :494-537：

  • IsJsonCompatible<T>：递归判断能不能安全落盘（函数、undefined、 Symbol 都判假）
  • InvalidJsonKeys<T>：反向找出哪个键不合法，报错能指到字段
  • JsonRepresentation<T>：把内存类型映射成「落盘后的形态」

为什么值得：details 的唯一归宿是 jsonl 文件（M10）。塞 Date 进去落盘 变字符串，塞 Map 进去变 {}——错误在落盘那一刻才暴露。M06 §3.5 （m06:367-390）是这个设计的完整动机。

Python 只有 TypeVar + 重载能近似，没有真正的条件类型。

条件类型里还能就地声明一个类型变量，用 infer：

ts
// packages/chord/src/contract.ts:417-424（节选）export type ImplementationOf<C, P = unknown> =	C extends RemoteContract<infer D> ? ... : never;

读作"如果 C 长得像 RemoteContract<D>，就把那个 D 记下来"。 as 是断言（不检查、我说了算），infer 是反推（检查，并从里面取出一个 类型变量）——两者长得很像，方向正好相反。正文里 M12 §3.4 用它把 contract 的类型参数掏出来。

2.6 satisfies：检查，但别改我的类型

ts
// packages/coding-agent/src/core/keybindings.ts:171} as const satisfies KeybindingDefinitions;

as const 把对象冻成字面量类型（键名保留、值不可变），satisfies 再拿它 去比对 KeybindingDefinitions 的形状。叠加效果：既被校验，又保留字面量 的精确类型——这正是写配置表最想要的。

对比标注写法 : KeybindingDefinitions：校验过了，但类型被放宽，字面量 信息丢了。

satisfies 在正文出现六次。例如 agent-loop.ts:620 } satisfies FinalizedToolCallOutcome;——返回值不写标注而用 satisfies， 就是为了让调用方拿到精确的联合成员。

2.7 as const：把字面量冻成常量

ts
// packages/coding-agent/src/core/tools/bash.ts:47} as const;

工具定义里到处是这个。bash.ts:44-47 给的是工具的提示词贡献：

ts
// packages/coding-agent/src/core/tools/bash.ts:44-47export const bashToolSystemPromptContribution = {	snippet: "Execute bash commands (ls, grep, find, etc.)",	guidelines: ["You can inspect PI_* environment variables …"],} as const;

不加 as const 时，snippet 被推断成 string、guidelines 被推断成 string[]；加了之后是字面量类型与 readonly ["…"]，拼进提示词时不会再 被当成任意字符串。同类写法在工具定义里出现二十多次（edit.ts:48、 grep.ts:37 都是）。M02 那张包表也是这么写的（m02:524）。

Python 没有等价物：字符串字面量本来就是那个值。

2.8 declare module：声明合并

ts
// packages/coding-agent/src/core/messages.ts:70-77declare module "@earendil-works/pi-agent-core" {	interface CustomAgentMessages {		bashExecution: BashExecutionMessage;		custom: CustomMessage;		branchSummary: BranchSummaryMessage;		compactionSummary: CompactionSummaryMessage;	}}

它不是「重新定义」，而是往一个已存在的 interface 里追加成员。agent 包里的 AgentMessage 由 CustomAgentMessages 的成员拼成，所以这段一旦 进入编译图，AgentMessage 就从 4 种变 8 种。

M06 §3 整节讲它的收益与三个副作用（m06:340-365）。Python 无对应机制。

四、Node 运行时：四个绕不开的内建对象

源码里出现频率最高、Python 里又没有直接对应物的四个：

Buffer——字节数组。M13 的 stdio 传输整节都在用它拼字节 （stdio.ts:181-207）。Python 里是 bytes + bytearray。

child_process——起子进程。MCP 的 stdio 传输本质是 spawn 一个服务器 进程再读它的 stdout（stdio.ts:449 的 killProcessTree）。Python 里是 subprocess。

AbortSignal——取消令牌。长任务都带一个 signal 参数，用户按 Esc 就 abort()。Python 里是 asyncio.Task.cancel()。

queueMicrotask——把一个函数排到当前同步代码之后、下一次 IO 之前。 scheduler.ts:1871 用它做「合并多次唤醒」：

ts
// packages/durable/src/harness/scheduler.ts:1868-1874（节选）if (this.#draining || !this.#enabled || !this.#closing) return;this.#draining = true;queueMicrotask(() => void this.#drain());

M11 §五讲了这个循环的全部意义：没有 while，靠「再排一次」驱动。 Python 里最接近 asyncio.call_soon。

五、Python 程序员的三个真陷阱

一，[] 和 {} 是 truthy。 Python 里空列表是假值，JS 里是真值。 所以源码判断空数组一律 .length === 0，不会写 if (!arr)。

二，== 会隐式转换，=== 不会。 源码里清一色 ===（biome 有规则拦着）。 "8" == 8 在 Python 里是 False，在 JS 里是 true。

三，.map() 返回新数组，.forEach() 返回 undefined。 Python 的 列表推导返回列表，生成器函数返回迭代器——JS 没有同款惰性版。
