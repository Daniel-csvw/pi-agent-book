E03

接口 —— 先造一条能回放的模型，再接真的

2,489 字 · 含 334 行代码 · 约 14 分钟

E02 结束后，loop.ts 还是硬绑 createMockProvider()。mock 有个天花板：它只会 按三条规则说话，你没法用它验证「流式解析对不对」「工具参数分片拼没拼上」。

这一章把 provider 抽成真接口，然后写两份实现：

  • fixture：把一段回复录成文本，离线回放。零凭据、零网络、可进测试。
  • openai：一个 POST，读 SSE，边读边翻译成同样形状的 chunk。

三个问题：

  1. 回放要录什么？录原始 SSE，还是录我们自己的 chunk？
  2. 网络给来的是字节流，不是一个事件一个事件——怎么把它切成完整事件？
  3. 没有 API key 时，怎么证明真模型那段代码是对的？
text
  runAgent     |     |  provider.stream(messages, tools, signal)     v  ProviderChunk: text / toolCall / done     ^                    ^     |                    |  mock（三条规则）      fixture（回放） / openai（SSE）

二、先定录制格式，再写解析器

第一版我录的是原始 SSE，一行一个 data: {...}。写了两条带子之后发现一个硬 约束：书里的代码块每行不能超过 80 列。 而 OpenAI 的 tool_calls delta 长这样 （真实录制，一行）：

text
data: {"choices":[{"delta":{"tool_calls":[{"index":0,"id":"call_9",...    "function":{"name":"read","arguments":"{\"path\":\"README.md\"}"}}]}}]}

一行 158 列。压不进书里，也就压不进「看教程就能复现」这条原则。

于是我换了分工：回放不负责解析方言，只负责重放 chunk。 带子里存的就是 ProviderChunk，一行一条；SSE 的方言只在 openai.ts 里出现一次。两个直接好处：

  • 带子可读、可手写、长度可控，坏一行报行号；
  • 回放器不依赖任何 provider 细节，将来接 Anthropic 也不用改它。

代价是：fixture 不能替 openai.ts 测 SSE 解析。那就用一个本地 http 服务器来测 （第七节），比录制更可靠。

判断一：带子必须有一条 done 结尾。 少了它不会报错——我删掉最后一行试了， 循环照样给出一个「正常」的结果：

bash
node tmp-nodone.ts
text
turns=1 stop=stop

看着没问题，但这句 stop 是 loop.ts 里的初始值，不是模型报的原因。真模型 如果是被 length 截断，你也会记成 stop，然后去查一个不存在的问题。所以 回放器在创建时就拦：

text
ERR: fixtures/tmp-bad.jsonl 最后一行必须是 done

判断二：坏行报行号。 带子是手写的，截断、少个引号都常见：

text
ERR: fixtures/tmp-bad2.jsonl:2 不是 JSON：not-json

第 2 行——有这个数字，修法就只有一种；没有它，你只能打开文件数。

判断三：未知类型要拦。 JSON.parse 只保证是合法 JSON，不保证是合法 chunk。 {"type":"thought"} 能过 parse，但下游 loop.ts 的 if/else 会把它当 done 分支吞掉（那个 else 就是给 done 用的）。所以这里先拦一道。

stream() 是 async * 但内部没有 await——它是异步可迭代协议的要求，不是 为了异步而异步。yield 让调用方用 for await 拉，和真网络流完全同形。

import type {  Message,  Provider,  ProviderChunk,  StopReason,  Tool,} from "../types.ts";export interface OpenAIOptions {  baseUrl?: string;  apiKey?: string;  model?: string;}/** tool_calls 分片暂存：id 只来一次，name 与 args 可能来好几段。 */interface PendingCall {  id: string;  name: string;  args: string;}function wireMessages(messages: Message[]) {  return messages.map((message) => {    if (message.role === "system" || message.role === "user") {      return { role: message.role, content: message.content };    }    if (message.role === "assistant") {      const text = message.content        .filter((block) => block.type === "text")        .map((block) => block.text)        .join("");      const calls = message.content        .filter((block) => block.type === "toolCall")        .map((block) => ({          id: block.id,          type: "function",          function: {            name: block.name,            arguments: JSON.stringify(block.args),          },        }));      if (calls.length > 0) {        return { role: "assistant", content: text || null, tool_calls: calls };      }      return { role: "assistant", content: text };    }    return {      role: "tool",      tool_call_id: message.toolCallId,      content: message.content,    };  });}function mapReason(reason: string | null | undefined): StopReason {  if (reason === "tool_calls") return "toolUse";  if (reason === "length") return "length";  return "stop";}/** 真模型：只有一个 POST，流式读 SSE，边读边翻译成 chunk。 */export function createOpenAIProvider(options: OpenAIOptions = {}): Provider {  const env = process.env.OPENAI_BASE_URL ?? "";  const baseUrl = (options.baseUrl ?? env).replace(/\/$/, "");  const apiKey = options.apiKey ?? process.env.OPENAI_API_KEY ?? "";  const model = options.model ?? process.env.OPENAI_MODEL ?? "gpt-4o-mini";  return {    name: "openai",    async *stream(messages, tools, signal) {      if (!baseUrl || !apiKey) {        throw new Error("缺 OPENAI_BASE_URL 或 OPENAI_API_KEY");      }      const response = await fetch(`${baseUrl}/chat/completions`, {        method: "POST",        signal,        headers: {          "content-type": "application/json",          authorization: `Bearer ${apiKey}`,        },        body: JSON.stringify({          model,          stream: true,          messages: wireMessages(messages),          tools: tools.map((tool) => ({            type: "function",            function: {              name: tool.name,              description: tool.description,              parameters: tool.parameters,            },          })),        }),      });      if (!response.ok || !response.body) {        const body = await response.text();        throw new Error(`HTTP ${response.status}: ${body.slice(0, 200)}`);      }      const reader = response.body.getReader();      const decoder = new TextDecoder();      const pending = new Map<number, PendingCall>();      let buffer = "";      while (true) {        const { done, value } = await reader.read();        if (done) break;        buffer += decoder.decode(value, { stream: true });        const parts = buffer.split("\n\n");        buffer = parts.pop() ?? "";        for (const part of parts) {          for (const line of part.split("\n")) {            const data = line.startsWith("data:") ? line.slice(5).trim() : "";            if (!data || data === "[DONE]") continue;            const event = JSON.parse(data);            const choice = event.choices?.[0];            if (!choice) continue;            const delta = choice.delta ?? {};            if (delta.content) {              yield { type: "text", text: delta.content } as ProviderChunk;            }            for (const call of delta.tool_calls ?? []) {              const index = call.index ?? 0;              const slot =                pending.get(index) ?? { id: "", name: "", args: "" };              if (call.id) slot.id = call.id;              if (call.function?.name) slot.name += call.function.name;              if (call.function?.arguments) {                slot.args += call.function.arguments;              }              pending.set(index, slot);            }            if (choice.finish_reason) {              for (const [index, slot] of pending) {                let args: Record<string, unknown> = {};                try {                  args = JSON.parse(slot.args) as Record<string, unknown>;                } catch {                  args = { _raw: slot.args };                }                yield {                  type: "toolCall",                  id: slot.id || `call_${index}`,                  name: slot.name,                  args,                } as ProviderChunk;              }              pending.clear();              const stopReason = mapReason(choice.finish_reason);              yield { type: "done", stopReason } as ProviderChunk;            }          }        }      }    },  };}export type { Tool };

五段，逐个说。

第一段：wireMessages——出站翻译。 我们要发给模型的只有四种消息，但形状 不等于 OpenAI 的形状：

  • assistant 在我的模型里是 content: ContentBlock[]，OpenAI 要的是 content: string | null 加一个并列的 tool_calls 数组。所以 text 块 join("")，toolCall 块折成 {id, type, function:{name, arguments}}。
  • arguments 必须是字符串，不是对象。所以这里 JSON.stringify(block.args)。 反过来入库时再 JSON.parse——来回一趟，就是「对象 ↔ 字符串」的边界。
  • content: text || null：只要带了 tool_calls，text 允许为空，但不能是空字符串 （部分严格实现会 400）。
  • tool 消息的字段名是 tool_call_id，不是我们的 toolCallId。

第二段：一个 POST，stream: true。 没有 SDK、没有重试、没有 base64 图片、 没有 prompt cache 字段。signal 直接透传，取消就断。

第三段：错误要带状态码和响应体前 200 字符。 !response.ok 时如果只抛 HTTP 401，你会去猜是 key 错了还是模型名错了；带上 body 前 200 字符，通常 第一句就写着原因。

第四段：SSE 的切分。 这是最容易写错的地方。reader.read() 给你的是任意 长度的字节块，一个事件可能被劈成两半，也可能两个事件挤在一块。所以：

ts
buffer += decoder.decode(value, { stream: true });const parts = buffer.split("\n\n");buffer = parts.pop() ?? "";

split("\n\n") 是 SSE 的事件分隔；parts.pop() 取回的最后一段是不完整的， 必须留到下一次。decoder.decode(value, { stream: true }) 里的 stream: true 也是同一个道理：一个多字节汉字可能被劈在两个字节块之间。

第五段：tool_calls 分片。 真模型发工具调用时是一个片段一个片段来的：

text
{"index":0,"id":"call_9","function":{"name":"read","arguments":"{\"pa"}}{"index":0,"function":{"arguments":"th\":\"README.md\"}"}}

id 只来一次，name 和 arguments 会 += 累加。所以 pending 是按 index 索引的暂存表。等 finish_reason 出现，再一次性 yield 成完整的 toolCall。

args 解析失败时我塞 {_raw: slot.args} 而不是抛错——因为「模型给了坏 JSON」 是模型的问题，应该作为一条 tool 结果（或一次可观测的失败）回到循环里，而不是 让整个进程崩。

这个测试写了三版，前两版都是「能过但测不到东西」，三处坑都值得记：

第一坑：两次 res.write ≠ 两个网络块。 TCP 会把相邻的小写合在一起， 所以第一版「劈两半」的测试，实际收到的是一个完整事件——我把 openai.ts 的 buffer 复位注释掉，它照样绿。加了 await setTimeout(20) 之后才真劈开。 测试如果不是红的，它可能什么都没测。

第二坑：拆掉那行会怎么死。 把 buffer = parts.pop() ?? "" 删掉，重跑：

text
SyntaxError: Unterminated string in JSON at position 14    at Object.stream (.../src/provider/openai.ts:114:32)

半截事件被 JSON.parse，报的是「字符串没完」——它不是「缺少复位」这种话， 所以你得自己把行号映射回那两行切割逻辑。

第三坑：失败后测试不退出。 第一版没有 try/finally，抛错时 server.close() 被跳过，端口句柄悬着，node --test 卡到超时。测试代码也要管资源：finally 里关掉的不是服务器，是「失败时要能看见失败」。

顺手把回放器的测试也补齐（test/provider.test.ts，37 行）——它只断言类型序列 和参数，不依赖网络。

自检

  1. buffer.split("\n\n") 之后为什么必须 parts.pop()，而不是丢掉最后一段？
  2. 带子里没有 done 会怎样？错误在哪一层被拦住？
  3. provider 抛错时，loop.ts 的 emit 会发出哪些事件？为什么这不是 bug？

参考答案：

第 1 题：split 的最后一段可能是不完整事件（网络块边界正好落在事件中间）。 留到下一轮和新的字节拼起来，才可能凑成完整事件。丢掉它就等于丢掉模型的半句话， 而且不报错。

第 2 题：不会报错。实测 turns=1 stop=stop，一切看起来正常。危险就在这里： 那个 stop 是循环里的初始值，不是模型报的原因。真模型被 length 截断时，你 也会看到 stop，然后去查一个不存在的问题。所以错误要在最早能识别的那一层报， 并且报得像它真正的原因。

第 3 题：agent_start、turn_start 已发，agent_end 不会发——异常直接 穿透 runAgent。这不是 bug，是「谁负责兜底」还没定：宿主（CLI / TUI）知道怎么 告诉用户，库不该擅自吞掉异常。E08 的 CLI 会 catch 它、打一行人话、退出码 1。

十、与 Pi 的对照（可选）

Pi 的 provider 在 packages/ai/，一个 OpenAI Chat Completions 适配器就有 1,594 行（src/api/openai-completions.ts），而你刚写的是 159 行。它多出来 的是：

  • src/api/openai-completions.ts:542 的 for await (const chunk of ...) 之外， 还有 reasoning 明细、prompt cache、usage 计费、九家 provider 的字段兼容；
  • :640 起处理 delta.tool_calls，参数用 src/utils/streaming-json.ts 的 ToolCallArgumentsStream 做增量解析——比 我们的「拼成整串再 JSON.parse」更早发现坏 JSON；

结构同构：一个 POST，一个循环，一套分片。你现在这 159 行是删掉所有兼容性之后 的骨架，出问题时知道该往哪个方向加。
