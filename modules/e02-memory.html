E02

记忆 —— 四种给模型，多一种给自己

1,869 字 · 含 44 行代码 · 约 11 分钟

E01 的历史只有四种消息，正好等于模型能理解的四类角色。真实会话没这么干净：

  • 用户按了 Ctrl+B，把一段 bash 输出塞进对话——它不是用户说的，也不是模型说的；
  • 上下文快满了，你把前 20 条压成一段摘要——摘要得让模型看见，但它不是用户输入；
  • 界面要显示「已压缩 12 条」，模型不需要知道这个提示。

如果这些都硬塞进四种角色，模型会以为「用户刚才说了这句话」。等它开始 回答一句用户根本没说过的话，你才会发现历史被污染了。

这一章加一层：消息从四种变五种，多出来的那种永远不直接发给模型。

三个问题：

  1. 系统自己记的消息，凭什么不能直接进 prompt？
  2. 谁来保证「忘了一个新角色」时不会悄悄丢历史？
  3. 压缩之后，模型怎么知道之前发生过什么？
text
  AgentMessage（5 种）    system / user / assistant / tool / note                     |                     |  toLlm()  <-- 唯一出口                     v  Message（4 种）    system / user / assistant / tool                     |                     v                  provider

一、第五种：只给自己看

NoteMessage 的定义里有两个字段值得停一下：

<!-- file: examples/mini-agent/src/types.ts -->

ts
export interface NoteMessage {  role: "note";  kind: "summary" | "reminder";  text: string;  display: boolean;  timestamp: number;}

display 不是「要不要发给模型」，而是「要不要上屏」。这两个问题必须分开： 一条压缩摘要，模型要看（否则它不知道前文），用户未必要看（你要么折叠， 要么只显示一行提示）。反过来，一条「已重试 2 次」的提醒，用户要看，模型 不必看。

Pi 里对应的是 CustomMessage：role: "custom"，带 customType、display 和一个可选的 details。它同样进 transcript、同样默认不进 prompt。区别是 Pi 的 display 只是布尔值，真正决定「发不发」的是另一层投影。

二、闸门：一个 switch，缺一个角色就抛

所有发给模型的消息，只经过一个函数：

<!-- file: examples/mini-agent/src/messages.ts -->

ts
      case "note":        out.push({ role: "user", content: renderNote(message) });        break;      default: {        const unknown = message as { role?: string };        throw new Error(`unhandled: ${String(unknown.role)}`);      }

注意 note 的翻译方式：包成一条 user 消息，内容带 <note kind="...">。 这不是偷懒，而是所有 provider 都能表达的最小形式。代价是模型可能把 note 当成用户说的话——所以 note 的文本必须自带身份标签，就像 Pi 的压缩摘要前 缀 "The conversation history before this point was compacted..."。

default 分支是这一章真正的重点。它不是为了处理未知角色，而是为了在 你将来加了第六种消息却忘了改这里时，立刻炸掉。

三、别指望类型帮你兜底

你可能会想：AgentMessage 是个联合类型，漏掉一个 case，TypeScript 会报错。 在「有编译步骤」的项目里确实会。但 Node 22.19 起直接跑 .ts 只做类型 擦除，不做类型检查。我实测过：

ts
const m = { role: "note" } as AgentMessage;const x: never = m;   // 一行类型错误console.log("ran");

node tmp-never.ts 输出的是 ran。类型错误一行都没报。

所以判断「有没有漏角色」只能放在运行时。现在故意塞一个不存在的角色：

bash
node -e "import('./src/messages.ts').then(m => {  try { m.toLlm([{ role: 'unknown' }]) }  catch (e) { console.log('ERR:', e.message) }})"

真实输出：

text
ERR: unhandled: unknown

这就是一张能用的网：开发时你会立刻看到它，而不是等模型答非所问。

四、会话：一行一条，坏行报行号

历史要能跨进程。最小的做法是 JSONL：一行一条消息，追加写，从头读。

bash
node src/cli.ts --mock "你好" --session tmp-e02.jsonlnode src/cli.ts --mock "读 README" --session tmp-e02.jsonl

第二条命令会先读回第一条的历史，再继续。文件里现在是 6 行：两轮的 user / assistant / tool / assistant。

读的时候必须防坏行，否则一行截断就能让整个会话打不开：

<!-- file: examples/mini-agent/src/session.ts -->

ts
      try {        session.messages.push(JSON.parse(line) as AgentMessage);      } catch {        throw new Error(`${file}:${index + 1} 不是合法 JSON`);      }

我手动往文件末尾加一行 not-json，再读：

text
ERR: tmp-e02-bad.jsonl:7 不是合法 JSON

行号是必须的。没有行号，你只能打开文件自己数；有了行号，修复动作是确定的： 删掉第 7 行，或者把它前面的引号补齐。

五、压缩：先设一道闸，再谈策略

E01 的历史会无限增长。第一版压缩不需要模型，只需要一个判断：

<!-- file: examples/mini-agent/src/compact.ts -->

ts
  if (tokensBefore <= threshold || messages.length <= keep) {    return { messages, compacted: false, tokensBefore, dropped: 0 };  }  const cut = messages.length - keep;

estimateTokens 用的是 JSON 字符数 / 4。这个数字不准，误差可以到 30%， 但它比「不估」强得多：你至少有一道闸，而不是等接口返回 400。

过闸之后，早期消息被替换成一条 note，末尾 keep 条原样保留。我用 10 条 长消息、阈值 60、保留 3 条跑了一次：

text
compacted true dropped 7 len 4 first note

四个数字，四个都能测：压了没有、丢了几条、剩几条、第一条是不是摘要。

但别把这一版当答案。M09 会让你改掉三个直觉：

  1. 只看 token 不够。 Pi 先看预算，再看消息边界，两道闸门缺一不可。
  2. 整段摘要会切断工具调用对。 一个 toolCall 和它的 toolResult 必须 一起进、一起出，否则下一轮接口直接报错。
  3. 摘要里只留对话会丢文件。 模型记得「我们改过 index.ts」，但忘了改到 哪一步；Pi 的摘要会带当前工作集，而不是只复述聊天。

所以这一章给你的是「能跑的压缩」，不是「正确的压缩」。差别在 E04 之后你 会看得更清楚。

六、实验：四组，都有判据

# 命令 / 改动 判据
1 toLlm([{role:"unknown"}]) 抛 unhandled: unknown
2 往会话文件塞 not-json 报错带 :7
3 阈值 60、keep 3、10 条 compacted true dropped 7
4 不加 --session 再跑一次 历史清空，说明状态只在文件里

实验 4 最容易被跳过。它证明的是：进程无状态。 所有记忆都在文件里， 关掉终端不等于丢会话，换个目录启动就是另一个会话。

七、小结

  • 消息的「超集」不是为了多，而是为了让「给模型看」和「给自己看」分开。
  • 唯一出口是一道函数闸门；漏角色必须在运行时抛，不能指望类型擦除。
  • 会话是追加日志，行号是修复入口。
  • 压缩的第一版只要一道阈值就够，但要知道它哪里不对。

十、三个常见误区

「多一种消息就要多一种 provider 角色。」 provider 的方言是外部约束，不是你说了算。Pi 的 Message 永远只有四种， 多出来的全部在投影层翻译掉。

「JSONL 太土，应该上 SQLite。」 追加写 + 逐行读的协议只有一句话，坏行能定位，迁移成本为零。等你有并发写、 跨会话检索的需求再换，别在第一天换。

「压缩就是摘要，摘要越短越好。」 压得太狠，模型会反复问「我们刚才在做什么」。摘要的目标不是短，是让下一 轮能接着干：当前任务、已改文件、未决问题，三样都不能丢。
